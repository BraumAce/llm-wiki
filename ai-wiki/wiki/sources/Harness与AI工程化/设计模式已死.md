# 设计模式已死？

> 来源：腾讯云开发者社区（王顺驰），2026-06-09

## 核心观点

当 AI 系统拥有足够复杂的任务和自治能力时，它最终会收敛到与人类工程设计相同的底层抽象。AI 自发地演化出了一套类似设计模式的结构，就连 Harness 本身也跟设计模式有莫大的关联性。不管编程范式如何变化，经典始终是经典。

## 10 个经典模式在 AI Agent 中的回归

### 1. 单例模式（Singleton）

确保一个类只有一个实例，提供全局访问点。并发安全：Go 的 `sync.Once`。

**Agent 新应用**：全局配置管理器、Agent 共享状态、并发安全初始化。

### 2. 工厂模式（Factory）

将对象创建过程封装起来，由子类决定实例化哪一个类。

**Agent 新应用**：根据任务类型动态创建不同 Agent、工具实例化。

### 3. 观察者模式（Observer）

定义对象间一对多依赖关系，状态改变时自动通知。

**Agent 新应用**：Agent 间事件通知、状态变更广播、消息系统。

### 4. 装饰者模式（Decorator）

不修改对象自身，动态添加额外职责。

**Agent 新应用**：Agent 能力动态增强、中间件链（日志/缓存/安全控制叠加）。

### 5. 策略模式（Strategy）

定义一系列算法，封装起来使它们可以互相替换。

**Agent 新应用**：运行时切换推理策略、不同任务用不同算法。

### 6. 适配器模式（Adapter）

使原本不兼容的接口能够一起工作。

**Agent 新应用**：不同 LLM API 适配、工具接口统一、新旧系统迁移。

### 7. 代理模式（Proxy）

为另一个对象提供代替或占位符，控制访问。

**Agent 新应用**：Agent 代理、延迟初始化、访问控制、远程代理。

### 8. 命令模式（Command）

将请求或操作封装为一个对象，解耦发送者和接收者。

**Agent 新应用**：任务封装、撤销/重做、批处理调度、宏录制。

### 9. 组合模式（Composite）

将对象组合成树状结构，表示"部分-整体"层次。

**Agent 新应用**：Agent 层级结构、Multi-Agent 树状组织。

### 10. 迭代器模式（Iterator）

顺序访问聚合对象中的各元素而不暴露内部表示。

**Agent 新应用**：遍历 Agent 结果集、流式处理、分页查询。

## 关键洞察

1. 设计模式没有死 — AI 自发演化出类似结构
2. Harness 本身就是设计模式的体现 — 任务拆分、Agent 编排是对经典模式的新应用
3. 底层抽象是不变的 — 治愈 AI FOMO 焦虑
4. 经典始终是经典 — 软件工程底层规律不会因 AI 改变，变的是表达形式
