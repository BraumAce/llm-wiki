## 核心思路

用 **Wiki 知识库（KB）** + **Skills 技能包** 来增强 AI 编码助手在企业级研发中的能力。知识库存业务知识，技能包规范研发流程。

## 知识库设计

- 用 Markdown 存储，结构化为 entity（实体）、concept（概念）、query 等类型
- 支持 source 源码摄入，自动从代码仓库学习生成知识页
- 通过 git 管理版本，crontab 定时同步

## 技能包体系

- `kb-tech-solution` — 技术方案编写
- `kb-tech-review` — 技术评审
- `kb-just-coding` — 编码实现
- `kb-test-pre` — 测试准备
- `kb-problem-solve` — 问题排查

## 评测系统

### KB 健康体检
- 15 条黄金评测集 + LLM Judge 双 seed 打分
- 用 σ₀ 噪声基线（实测 0.236）区分真改进和噪音
- 单 task 分差 |Δ| ≥ 3σ₀ = 0.71 则为真变化（99.7% 置信）

### 横向对比
- A 组（KB+Skills）vs B 组（Baseline）
- 主流程 **+12 分**，问题排查 **+4.3 分**

### 迭代评测
- 验证 Skill 优化是否正向
- v2 技术方案 +8.7，评审 -0.7（旧版 checklist 覆盖更稳定）

### 评测防作弊
- 脱敏盲评
- 模型分离（Opus 4.6 生成，Opus 4.7 评分）
- 平台分离（Claude Code 生成，Aone-Copilot 评分）

## 关键发现

- 证据驱动（新版 Skill）vs 流程驱动（旧版 checklist）各有优劣
- 前者发现力强但覆盖不稳定，后者稳定但深度有限
- 技术评审 Skill 需要适当补充 checklist + 反编造规则

## 未来方向

- **Harness 规则体系**：LLM 是执行者，Harness 是导演 — 编排、门禁、护栏、回滚
- **SKILL 自动优化**：评测系统 + 用户反馈 → LLM 定期给出优化建议 → 评测验证正向
- **跨多知识库发展**：覆盖所有业务范围

## 详细评测数据

### KB 健康体检问题

| 问题类别 | KB 问题 |
|---------|---------|
| 类页未建齐（死链） | concept 引用 [ImplClass]，但无对应页（6项业务） |

### 横向对比评分标准

**主流程评分：**
- 技术方案（30%）：业务覆盖度、设计合理性、详细设计粒度、风险与回滚
- 技术评审（20%）：问题识别、编造检测、建议可操作性、评审独立性
- 编码实现（30%）：修改位置、业务逻辑、项目风格、编译检查
- 测试准备（20%）：场景覆盖、用例可执行性、数据需求清晰度、异常边界

**问题排查评分：**
- SLS 查询有效性（25%）
- 代码定位与证据链完整性（25%）
- 根因可信度（25%）
- 修复建议合理性（15%）
- 复现/验证步骤（10%）

## 知识库更新管理

- **crontab 本地定时任务**：每周一次远程代码仓库 diff
- **kb-sync 技能**：开发方人工更新 → push 到 git；使用方 pull 自动拉取
- 后续 push 到远程仓库需要增加 CR

## SKILL 用户体验优化

1. **MCP 工具收拢**：所有工具统一到"自动化测试 MCP 服务"，只连一个 MCP
2. **多平台兼容**：Claude-code, Aone-Copilot, OpenClaw
3. **SLS 日志**：通过阿里云 SDK + Python 脚本 + 配置 AK/SK 跳过鉴权
4. **Aone 发布工具**：通过安装 a1 CLI 实现与 MCP 服务一致的功能

## 测试准备 & 自动化测试优化

- 自动化测试 MCP 服务新增查询 odps、holo、igraph、oceanBase、mySql 的工具
- 抓取存储表知识放到知识库
- LLM 自己写 SQL，自己找对应表，查询需要的入参
- 使用查询工具结合测试场景验证数据最终一致性
- 开子 agent 分析不符预期原因，按照 SOP 执行代码修复

## 问题排查优化

- 首先拿到报错信息
- 用 a1-CLI 拿到最近一周发布的具体内容
- 结合报错判断是否由发布导致
- 若非发布导致，再结合 KB 和代码仓库分析原因

## 全自动化发展

核心思想：LLM 是执行者，Harness 是导演 —— 不替 LLM 思考，但负责编排、门禁、护栏、回滚。
