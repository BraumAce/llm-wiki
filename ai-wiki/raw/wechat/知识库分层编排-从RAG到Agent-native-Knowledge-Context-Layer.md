# 知识库分层编排：从 RAG 到 Agent-native Knowledge Context Layer

知识库的四种范式各有局限，核心缺失是层次感知与角色适配。金字塔模型将知识分为五层，通过分层检索与图谱关联，让AI按角色、层级精准定位答案。

## RAG 的三个结构性缺陷

1. **每次从零推导** — LLM 每次都得重新找到并拼接片段，没有任何中间成果被保留（Karpathy 指出："the LLM is rediscovering knowledge from scratch on every question"）
2. **无法连点成线** — 平坦向量检索无法通过共享属性连接分散信息（Microsoft GraphRAG 研究指出的 baseline RAG 失败模式）
3. **粒度混乱** — 向量空间不区分抽象层次，"设计原则"和"代码实现"在语义上可能很近，但服务于完全不同的认知需求

## 四大知识库范式

| 范式 | 核心思想 | 知识积累 | 知识关联 | 层次感知 | 角色适配 |
|------|---------|---------|---------|---------|---------|
| Naive RAG | chunk → embedding → 向量检索 | ❌ | 默认无 | 默认无 | 默认无 |
| LLM Wiki | 持续编译的知识工件（Karpathy 提出） | ✅ | 手动 wikilink | 按主题分页 | ❌ |
| Graphify | 代码/文档映射为知识图谱 | ✅ | ✅ 自动推断 | 按社区分组 | ❌ |
| GraphRAG | 图谱增强检索 + 社区摘要 | 部分 | ✅ 自动推断 | 分层社区 | ❌ |

## 金字塔知识库（Pyramid KB）

五层分层设计，按稳定性和抽象度划分：

| 层 | 职责 | 稳定性 | 类比 |
|----|------|--------|------|
| L1 原则 | SOLID / KISS / YAGNI | 年级 | 宪法 |
| L2 架构 | 架构决策记录 ADR | 季度级 | 法律 |
| L3 规范 | 编码标准 ESLint 规则 | 月级 | 规章 |
| L4 实现 | 代码模板 SDK 文档 | 周级 | 手册 |
| L5 经验 | 故障复盘 运维日志 | 天级 | 判例 |

### 跨层关联（7 种有向边）

governs / defines / constrains / implements / validates / feedback / cross_ref

### 角色感知

- 架构师：L1 + L2
- 开发者：L2 + L3 + L4
- 运维/SRE：L4 + L5
- 新人：L1→L2→L3→L5 全链路导航

每个角色有独立的 context_budget 和 priority_order，按优先层顺序逐层填充直到预算用完。

### 检索机制对比

- 向量检索：语义相似度，全量文档，API 调用 1 次
- 金字塔分层检索：分层关键词打分 + 图谱扩展，角色可访问层子集，0 次 API 调用（纯本地）

最优组合：金字塔做分层定位 → 向量检索补代码级深度 = 结构化导航 + 精确细节的互补。

## 知识保鲜

- **腐烂形式**：静默过期、层级漂移、覆盖盲区
- **保鲜原则**：每层不同审查周期、用审计发现问题而非人工巡检、变更驱动更新而非日历驱动
- **增量同步**：审计 → 摄入 → 后审计，去重四策略（checksum + entry ID 双重校验）

## 实战测评

831 篇源文档、14 个代码服务、5 个业务域，200 条 QA pair 对比测评（RAGAS 框架）。

## 核心结论

> 知识库的终极形态不是"更大的向量库"，而是"更聪明的知识路由器"。分层是骨架，图谱是神经，角色感知是大脑，增量同步是新陈代谢。四者合一，才是 Agent-native 的知识基座。
